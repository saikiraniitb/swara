# Control Contract v0

## Public synthesis boundary

Swara Speech accepts a versioned, structured `SynthesisRequest`. It is independent of plain text callers, any Director implementation, model internals, and natural-language prompting.

```text
SynthesisRequest
├── content: Content
│   ├── text
│   └── default_language
├── speaker: SpeakerRef
├── pronunciation: PronunciationInput
├── performance: PerformancePlan
└── generation: GenerationOptions
```

`PronunciationInput` is deliberately a first-class linguistic concern. It is not a performance instruction and may be compiled by the pronunciation frontend without looking at `PerformancePlan`.

## Contract types

```yaml
Content:
  text: string
  default_language: bcp47
SpeakerRef:
  speaker_id: string
PronunciationInput:
  document_id: string | null
  overrides: [PronunciationOverride]
PerformancePlan:
  schema_version: swara.performance.v0
  emotion: Emotion | null
  emotion_intensity: 0.0..1.0 | null
  pace: {relative: 0.5..2.0} | null
  emphasis: [{source_range: {start: int, end: int}, level: 1..3}]
  pauses: [{after_source_offset: int, duration_ms: integer}]
  style: [StyleTag]
GenerationOptions:
  seed: integer | null
  max_duration_ms: integer | null
  deterministic: boolean
```

`Emotion` and `StyleTag` are finite enums, not arbitrary prompt strings. All ranges are anchored to source-text offsets. The schema has no `prompt`, `instruction`, or free-form `style_text` field.

## PerformancePlan classification

| Classification | Fields | Contract meaning |
|---|---|---|
| V0_EXECUTABLE | Neutral/default plan only | V0 promises no learned artistic control. An empty plan is valid and means neutral/default delivery. |
| V0_REPRESENTABLE | `emotion`, `emotion_intensity`, `pace`, `emphasis`, `pauses`, finite `style` tags | API validates, transports, and reports these fields without claiming the v0 speech model executes them. |
| FUTURE (not in v0 public contract) | Narrative role, scene understanding, narrative reasoning, arbitrary textual prompts, music, ambience, spatial audio, volume/mastering | Omitted rather than accepted as unknown fields. |

The absence of execution for V0_REPRESENTABLE fields must be visible in a future `RenderReport`; silent artistic-control claims are forbidden.

## Control Adapter boundary

`ControlAdapter` is a Swara Speech protocol:

```text
external structured performance description
                 ↓
          ControlAdapter
                 ↓
      Swara-native PerformancePlan
```

It validates/maps external structured data into `PerformancePlan`; it does not parse content, resolve pronunciation, select model tokens, or invoke a generator. An adapter is optional. It may be supplied by an integration later, but Swara Speech owns the target type and has no dependency on that integration.

## Plain-text default path

```text
text → default request builder → SynthesisRequest → Swara Speech
```

A future `swara.synthesize("Hello world")` convenience call delegates to the default request builder. It supplies the configured default language, default speaker ID, empty pronunciation input, neutral `PerformancePlan`, and default `GenerationOptions`. It does not require a Director, a ControlAdapter, or a caller-created plan.

## Ownership of controls

| Concern | Owner / route |
|---|---|
| Pronunciation | Swara linguistic frontend and model conditioning |
| Speaker identity | Swara speaker conditioner/model conditioning |
| Emotion, style, pace, emphasis | `PerformancePlan` → model conditioning later |
| Pauses | `PerformancePlan` → primarily orchestration/renderer later; silence need not be generated by a neural model |
| Volume | Renderer/mastering later; excluded from v0 neural speech contract |
| Music, ambience, spatial audio | Not Swara Speech |
| Scene understanding, narrative reasoning | External Director responsibility; excluded from this repository |
