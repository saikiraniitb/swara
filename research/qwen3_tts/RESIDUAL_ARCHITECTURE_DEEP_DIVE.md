# Qwen3-TTS 12 Hz Talker residual architecture

This is a source-level trace of the official Qwen3-TTS implementation at
`/Users/saikiran/Documents/tts-reference/qwen3-tts`, commit
`022e286b98fbec7e1e916cb940cdf532cd9f488e`. It is intentionally limited to
primary and residual speech-token generation.

## 1. Primary Talker

The primary model is
`Qwen3TTSTalkerForConditionalGeneration` in
`qwen_tts/core/models/modeling_qwen3_tts.py:1564`. Its contained
`Qwen3TTSTalkerModel` (`:1427`) is a decoder-only causal Transformer. The
0.6B Base configuration reports:

* hidden size 1024, 28 decoder layers, 16 attention heads / 8 KV heads
* Talker vocabulary 3072; `codec_head = Linear(1024, 3072, bias=False)`
* 16 code groups in the actual 12 Hz model
* text embedding table 151,936 × 2,048, projected by `text_projection` to
  1,024 dimensions

The public generation path constructs a multimodal causal sequence in
`qwen_tts/core/models/modeling_qwen3_tts.py:1970–2240`:

1. text/control IDs are embedded by the Talker text embedding and projected;
2. codec control/speaker/BOS states are added, with special codec IDs for
   language, thinking/control, pad, BOS and EOS;
3. text states remain available as `trailing_text_hidden` for each speech step;
4. the Talker decoder produces a 1,024-dimensional hidden state;
5. `codec_head` predicts the primary codec stream (code group 0);
6. that primary token starts the sub-talker; the completed 16-token frame is
   then summed into the next Talker input state.

At generation (`:1664–1687`), `input_ids` is the current primary token. Its
embedding is concatenated with the 15 residual embeddings generated by the
code predictor. These 16 embeddings are summed to one `(B,1,1024)` frame
state. The current trailing text state is added, and the Talker consumes that
state with KV cache. Thus the next frame sees the full preceding codec frame,
not codebook 0 alone.

## 2. Residual/sub-talker model

The residual model is
`Qwen3TTSTalkerCodePredictorModelForConditionalGeneration` (`:1156`) with
base `Qwen3TTSTalkerCodePredictorModel` (`:1015`). It is a separate causal
Transformer, not an MLP or GRU:

* 5 Transformer decoder layers
* hidden size 1024, FFN size 3072, 16 attention heads / 8 KV heads
* 15 independent codec embedding tables, each `Embedding(2048, 1024)`
* 15 independent output heads, each `Linear(1024, 2048, bias=False)`
* one code-predictor Transformer stack shared across the 15 positions

Therefore residual codebooks are autoregressive CB-by-CB, with independent
input embeddings and independent output projections, but shared Transformer
layers/norm/rotary positions.

### Confirmed residual computation graph

For one frame (`B` examples, `D=1024`, 16 code groups):

```text
talker_hidden:             (B, D)
primary codec token CB0:   (B,)
CB0 embedding:             (B, D)

sub_input[0] = talker_hidden                         # (B, D)
sub_input[1] = Talker.codec_embedding(CB0)           # predicts CB1
sub_input[2] = code_embedding[0](CB1)                # predicts CB2
...
sub_input[15] = code_embedding[13](CB14)             # predicts CB15

sub_sequence = stack(sub_input)                      # (B, 16, D)
sub_hidden = CodePredictorTransformer(sub_sequence)  # (B, 16, 1024)

logits[CB1]  = lm_head[0](sub_hidden[:, 1])           # (B, 2048)
logits[CB2]  = lm_head[1](sub_hidden[:, 2])
...
logits[CB15] = lm_head[14](sub_hidden[:, 15])
```

The implementation is `forward_sub_talker_finetune` at `:1612–1633`.
`codec_ids` has shape `(B,16)` and `talker_hidden_states` `(B,1024)`.

At inference, `Qwen3TTSTalkerForConditionalGeneration.forward` (`:1669–1687`)
calls `code_predictor.generate(max_new_tokens=15)`. The predictor begins with
the Talker hidden state plus the primary embedding, then generates CB1,
feeds CB1 through its own embedding, generates CB2, and so on. The generated
residual sequence is `(B,15)`; concatenating the primary gives `(B,16)`.

## 3. Training behavior

The public fine-tuning path is visible in `finetuning/dataset.py` and
`finetuning/sft_12hz.py`.

`prepare_data.py` writes tokenizer output directly as `audio_codes` lists;
the dataset comment explicitly identifies shape `(T,16)`. No delay/interleave
transformation is applied.

The collator (`dataset.py:153–218`) creates:

* `codec_ids: (B, sequence_length, 16)` containing all target codebooks at
  their frame positions;
* `codec_0_labels` for the primary stream, shifted by the causal Talker call;
* `codec_mask` selecting codec frame positions.

In `sft_12hz.py:89–99`, every frame position’s Talker input is the sum of:

* text embedding;
* primary codec embedding;
* all 15 residual codec embeddings, each from its own table.

The main Talker receives `input_embeddings[:, :-1]` and primary labels
`codec_0_labels[:, 1:]` (`:100–104`). This is teacher forcing for the primary
sequence and exposes the complete true previous/current codec-frame embedding
organization to the causal Talker.

For residual training, `forward_sub_talker_finetune` receives true `(B,16)`
codec frames and true `talker_hidden_states` (`:107–113`). The sub-talker
sequence therefore uses true CB0 and true CB1…CB14 embeddings while predicting
CB1…CB15. This is teacher forcing across residual positions. Its loss is the
model’s standard token cross-entropy over the `(B,15,2048)` logits. The SFT
script combines `primary_loss + 0.3 * sub_talker_loss`.

Generation uses predicted residual history instead; `generate()` updates the
code-predictor cache and advances `generation_steps`. This creates the normal
train/inference exposure difference, but the source confirms that CB1 itself
already has a dedicated Transformer/head path.

## 4. Temporal/codebook organization

Qwen’s 12 Hz tokenizer output is directly `(batch, frames, 16)` with no delay
pattern in `prepare_data.py`. The Talker’s *temporal* stream is causal across
frames. Within each frame, residual codebooks are a second causal sequence of
length 16. There is no Dia-style delayed/staggered codebook layout.

Special IDs are Talker vocabulary/control IDs, not codec-token values: the
0.6B config reports codec BOS 2149, EOS 2150, pad 2148, and language IDs such
as English 2050. Codec values themselves remain 0–2047. The collator places a
codec BOS before frame CB0 and EOS after the frame sequence; it masks losses
outside codec positions.

## 5. One-frame generation trace

```text
text/control + previous full codec-frame state
        ↓
Talker causal Transformer (28 × 1024)
        ↓
primary CB0 logits (3072-way Talker head)
        ↓ sample/argmax CB0
Sub-talker input: Talker hidden + CB0 embedding
        ↓ 5-layer causal code predictor
CB1 head → sample CB1 → embed CB1
CB2 head → sample CB2 → embed CB2
...
CB15 head → sample CB15
        ↓
sum embeddings of CB0…CB15
 + trailing/current text state
        ↓
cached Talker state for next temporal frame
```

## 6. Capacity accounting

Using the local 0.6B safetensors metadata, parameter counts are:

| Component | Parameters |
|---|---:|
| Qwen Talker total (including code predictor) | 905,788,672 |
| Qwen main Talker excluding code predictor | 764,218,368 |
| Qwen code-predictor Transformer layers/norm | 78,654,720 |
| Qwen 15 residual embeddings | 31,457,280 |
| Qwen 15 residual output heads | 31,457,280 |
| Qwen code predictor total | 141,570,304 |
| Swara v3.2 residual subsystem | ~3,254,528 |
| Swara v3.3 residual subsystem | ~14,293,248 |

Swara’s residual path is therefore orders of magnitude smaller than Qwen’s
separate 5-layer residual Transformer. Even v3.3’s independent heads do not
provide the shared deep residual sequence modeling Qwen uses.

## Confirmed versus unknown

**Confirmed from source:** independent 15-head residual outputs, 15 separate
input embeddings, 5-layer causal Transformer, true-frame teacher forcing in
`forward_sub_talker_finetune`, primary + all residual embeddings summed into
the next Talker frame, direct `(T,16)` data organization, and loss weighting
`primary + 0.3 × residual` in the public SFT script.

**Not published/ not established here:** exact pretraining corpus mixture,
sampling schedule, any private loss weighting beyond the public SFT path, and
the checkpoint’s internal optimizer history.
