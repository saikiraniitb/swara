## 1. Executive RCA

Swara has built dependable frontend, data, alignment, and codec infrastructure, but **no formulation tested so far — across three architecturally distinct generator families (16-codebook autoregressive Qwen-style, discrete flat-NeuCodec 65,536-way autoregressive, and non-autoregressive continuous-latent regression/flow-matching) — has produced legitimate, human-verified, unseen speech.** Every family shows the identical qualitative signature: near-perfect fit/memorization on 2 training utterances, and collapse to unusable output on held-out text once the training set grows to ~5 minutes / 32 utterances. This recurrence, across maximally different objectives (categorical cross-entropy vs. Huber regression vs. flow matching) and maximally different architectures (causal autoregressive vs. bidirectional non-causal), is the single strongest pattern in the evidence.

Two other findings materially shape interpretation:

1. **A prior, purpose-built ablation (v3.1 dependence diagnostic) found direct, high-confidence evidence that an earlier generator's primary-token stream was dominated by autoregressive acoustic history over text (14.6× KL-sensitivity ratio) — but a subsequent fix (v3.2 gated fusion) substantially restored text control**, producing an intelligible sentence when paired with ground-truth residual tokens. This means H2 (history dominance) was real for one specific architecture at one specific point in time, and was **not** an unfixable, intrinsic property of the family — it does not explain why later, architecturally unrelated formulations (non-autoregressive continuous regression, which structurally cannot suffer classic exposure bias) also failed to generalize.
2. **The evidentiary record for "did it sound like speech" is almost entirely incomplete.** Of ~15 experiments with a generation/synthesis component, only two (P1, and the Distill-NeuCodec codec-fidelity blind test referenced in the retrospective) have a completed human-listening verdict. Every continuous-target experiment (R0, B0/B1, C0/C0b/C1, F0) remains formally `HUMAN_REVIEW_REQUIRED` with a blank scorecard. One process gate was explicitly bypassed: R0 stated "No C0 implementation or training is authorized by this report" pending human listening, yet C0/C0b/C1/B0/B1 training proceeded without that listening ever being recorded.

**Is the common core (linguistic composer → encoder → alignment adapter → duration expansion → frame conditioning) itself the root cause?** The evidence supports **SUSPECT, not CONFIRMED**. The core-conditioning forensic (§6) establishes that this shared 160-dimensional path carries only character/grapheme identity, unit boundary/kind, and unit-sequence position — no explicit phoneme identity, no position-within-a-duration-expanded-unit signal, no stress/syllable structure, and no prosody. All frames of one duration-expanded unit receive a byte-identical conditioning vector; any distinguishing information for the /k/-onset vs. vowel-center vs. release sub-structure of that unit must come from the generator's own architecture (autoregressive history, or bidirectional attention to neighboring units), not from the conditioning itself. This is a real limitation and a plausible contributing cause, but it is not proven sufficient to explain the failures alone, because the *identical* conditioning pipeline also supports near-perfect 2-utterance memorization in every family — meaning the conditioning is not so impoverished that it collapses all units to indistinguishable output; it is unproven whether it is fine-grained enough to support *generalizable* synthesis, which is a different, harder bar than memorization.

## 4. Failure-by-failure RCA

### 4.1 Generator v3 (Qwen 16-codebook, 30-min)
- **OBSERVED FAILURE**: train primary accuracy 0.9986 but validation primary ~0.09; validation free-running trajectories ~0.99 mutually similar regardless of held-out text (mode collapse).
- **DIRECT EVIDENCE**: `research/retrospective/SWARA_SPEECH_ENGINE_RETROSPECTIVE_V1.md` row "Generator v3"; `research/implementation/GENERATOR_V3_1_CORRECTION.md` identifies two concrete implementation defects: (1) `schedule_frames` used the *currently generated* frame count as denominator rather than a fixed utterance-wide budget, remapping earlier positions on every generation step; (2) the residual predictor accepted but never used its primary-token argument, so CB1 was architecturally independent of CB0.
- **ROOT CAUSE**: CONFIRMED (implementation bug — schedule instability + missing CB0→CB1 conditioning link).
- **CONTRIBUTING FACTORS**: unweighted primary+residual loss (vs. Qwen's reference 0.3× residual weighting).
- **RULED-OUT CAUSES**: codec/token provenance (separately audited clean in the v3.2 codec audit, transitively applicable).
- **WHAT WOULD FALSIFY THIS RCA**: if v3.1 (which fixed exactly these two defects) still showed the same shared-trajectory collapse. It did not — v3.1's max non-self similarity dropped to 0.075 — confirming the fix addressed this specific failure mode.

### 4.2 Generator v3.1 (schedule + CB0→CB1 fix)
- **OBSERVED FAILURE**: trajectory collapse fixed, but text-swap gate failed and residual accuracy remained ~1.2–1.5%.
- **DIRECT EVIDENCE**: `research/retrospective/SWARA_SPEECH_ENGINE_RETROSPECTIVE_V1.md` row "v3.1"; direct ablation in the v3.1 dependence diagnostic found `history_to_text_sensitivity_ratio = 14.606` and acoustic-history embedding L2 norm (~76-78) roughly 3.2-3.3× the linguistic embedding L2 norm (~23.5-23.9), *before* any Transformer processing.
- **ROOT CAUSE**: CONFIRMED for the primary/CB0 stream (acoustic-history domination via unnormalized additive fusion) — this is a purpose-built, directly-measured ablation, not a correlation.
- **CONTRIBUTING FACTORS**: no per-path normalization before fusion; fusion gates were fixed (not learned) prior to v3.2.
- **RULED-OUT CAUSES**: residual-stream failure is NOT explained by this finding alone — the residual diagnostic (§4.3) shows the residual collapse begins before any autoregressive exposure is even possible, a distinct mechanism.
- **WHAT WOULD FALSIFY THIS RCA**: if gated, normalized fusion (v3.2) failed to restore text sensitivity. It did not — v3.2's primary/text gates passed and CB0+GT-residual synthesis produced an intelligible, correct sentence.

### 4.3 Qwen residual stream collapse (v3.1/v3.2/v3.3, CB1–CB15)
- **OBSERVED FAILURE**: CB1 teacher-forced accuracy only 6.45%, predicted entropy 2.70 bits vs. target 6.22 bits; later codebooks nearly constant. Persists after gated fusion (v3.2) and after independent-head replacement (v3.3, validation residual ~1.3%).
- **DIRECT EVIDENCE**: `research/implementation/GENERATOR_V3_2_RESIDUAL_DIAGNOSTIC.md`; `research/qwen3_tts/RESIDUAL_ARCHITECTURE_DEEP_DIVE.md` (Qwen's reference residual/sub-talker is a dedicated ~141.6M-parameter 5-layer causal Transformer with 15 independent embeddings+heads; Swara's is a single shared GRU cell, ~3.25M (v3.2) to ~14.29M (v3.3) parameters).
- **ROOT CAUSE**: CONFIRMED for the tested interventions (shared-GRU capacity/underfitting) — CB1 fails before any exposure-bias mechanism is even possible, ruling out exposure bias as the CB1-specific cause. HIGH-CONFIDENCE (not CONFIRMED) that capacity is the *ultimate* cause, since independent heads alone (v3.3) only partially improved it, meaning head-sharing was not the sole deficiency, and the retrospective explicitly disproves "residual output heads alone would solve it" (disproved assumption #12) without yet isolating whether shared-GRU recurrence depth, hidden width, or something else is the binding constraint.
- **CONTRIBUTING FACTORS**: unweighted training objective; small model-size regime (10-20M target) is an explicit project-level design decision, not itself shown to be the bottleneck (retrospective disproved assumption #11).
- **RULED-OUT CAUSES**: exposure bias (CB1 has no autoregressive history to be exposed to); codec/token provenance (separately audited clean, 848/848 exact match).
- **WHAT WOULD FALSIFY THIS RCA**: a residual model with materially more capacity/depth (approaching Qwen's reference design) failing identically at the same data scale. Not tested — the project stopped after v3.3 to do the reference-architecture deep dive instead of testing this directly.

### 4.4 N1-A / N1-B five-minute generalization (flat 65,536 / 8×4 FSQ, text+position only, no acoustic history)
- **OBSERVED FAILURE**: two-utterance memorization 100%; five-minute (32/8) validation exact-token accuracy 0.0 for both variants; generated audio judged "no recognizable voice, heavy disturbance."
- **DIRECT EVIDENCE**: `experiments/neucodec_n1_v1/reports/N1_FAILURE_LOCALIZATION.md`; codec oracle PASS rules out codec corruption; two-item text-only reproduction is exact, ruling out a general plumbing break; held-out bigram overlap only 35–43% (A) / 0–1.9% (B), i.e. generated tokens are individually plausible but their temporal transitions are off the learned manifold.
- **ROOT CAUSE**: CONFIRMED — held-out generalization failure with an off-manifold token-transition signature, classified `MULTIPLE_CONFIRMED` in the source document: (1) teacher-forced-learning failure on unseen text, (2) off-manifold temporal-transition distribution.
- **CONTRIBUTING FACTORS**: no acoustic-history conditioning at all in this architecture (by design, to isolate the text-to-frame mapping) — this rules out exposure bias as an explanation for N1 specifically, and points toward the text→acoustic-manifold mapping itself being under-learned at this data scale.
- **RULED-OUT CAUSES**: codec/token corruption; alignment parity break (explicitly re-verified identical between train and generation, "not the old variable-denominator v3 schedule bug").
- **WHAT WOULD FALSIFY THIS RCA**: if adding acoustic history (N2) alone fixed generalization at the same data scale without any other change. It did not — N2's five-minute run also failed (§4.5), meaning the missing acoustic-history channel was not the dominant N1-specific bottleneck at this scale either.

### 4.5 N2 (causal history) — 2-item exposure bias, then 5-min failure
- **OBSERVED FAILURE**: N2.0: teacher-forced accuracy 99.9%, free-running accuracy 100% for one memorized utterance but 0.204% for the other (diverged at frame 0). After self-conditioning stabilization, both reach exact free-running match. At 5-minute scale (32/8): validation accuracy 0.00108, max non-self similarity 1.0 (i.e. at least one pair of *different* held-out texts produced byte-identical output), bigram overlap with real streams 0–15%.
- **DIRECT EVIDENCE**: `experiments/neucodec_n2_history_v1/reports/n1_vs_n2.json`, `n2_rollout_metrics.json`, `n2_5min_metrics.json`; `research/retrospective/SWARA_SPEECH_ENGINE_RETROSPECTIVE_V1.md` rows "N2 causal history" / "N2 rollout stabilization" / "N2 five-minute."
- **ROOT CAUSE**: CONFIRMED for N2.0 (classic exposure bias — train/inference mismatch between true and self-generated history) and CONFIRMED as fixed by detached scheduled self-conditioning at 2-item scale. At 5-minute scale, the failure mode changes character (near-complete generation-collapse across different texts) and its cause is explicitly recorded as **UNKNOWN** by the project's own retrospective ("Formulation fails rung ... Why: alignment/prefix/target/data/capacity" left as an open question, `EXPERIMENT_EVIDENCE_MATRIX.md` row N2-5).
- **CONTRIBUTING FACTORS**: same 32/8 data-scale regime that also breaks every other family tested (see §5, H6 and §8 ranked cause #1).
- **RULED-OUT CAUSES**: the specific 2-item exposure-bias mechanism identified in N2.0 was directly fixed and confirmed fixed at that scale — it therefore cannot by itself explain the 5-minute failure, which persists despite the fix being present.
- **WHAT WOULD FALSIFY THIS RCA**: UNKNOWN is itself the honest state here; the project explicitly stopped and wrote a retrospective rather than guess further (see §9, Remaining Unknowns, question 1).

### 4.6 P2 (flat 65,536 AR, five-minute)
- **OBSERVED FAILURE**: train loss falls to 0.0198; validation CE rises to 12.275 (worse than the untrained baseline of ~11.52, i.e. below-chance); validation exact-token accuracy 0.139%; free-running max non-self trajectory similarity crosses the predeclared 0.90 collapse threshold at step 750 (0.9243).
- **DIRECT EVIDENCE**: `research/poc/diagnostics/P1_P2_ACOUSTIC_GENERALIZATION_FAILURE.md`, a full labeled RCA (the only such document in the repo for a generation architecture) attributing this to **three co-equal, independently confirmed causes**: (1) sparse statistical support for the 65,536-way target (80.97% singleton training IDs, 61.03% validation frames use a never-seen-as-training-target ID, 99.79% validation bigrams unseen); (2) exposure-bias-driven self-repetition attractor (self-transition rate 97.7% generated vs. 0.0857% in real targets; greedy argmax converts a small self-repeat probability advantage under self-generated history into deterministic loops); (3) tied 65,537×160 embedding/output head (78.78% of all parameters) whose output bias correlates 0.953 with log-token-frequency, meaning it substantially learned corpus frequency rather than class-discriminative structure.
- **ROOT CAUSE**: CONFIRMED, multi-cause (all three named above, explicitly ranked co-equal in the source RCA, not speculative).
- **CONTRIBUTING FACTORS**: single fixed teacher-forcing schedule; tiny (5-minute) data regime.
- **RULED-OUT CAUSES** (explicitly, in the source document): duration/alignment failure (GT-duration audio was already non-speech; frame/target equality verified exact); acoustic-history domination over text (controlled swap experiment: text-swap effect ≥ history-perturbation effect); flat-NeuCodec-representation-intrinsically-unviable (codec oracle works, P1 memorizes perfectly, and NeuTTS uses the identical 65,536-token representation at larger scale).
- **WHAT WOULD FALSIFY THIS RCA**: the 30-minute statistical-support audit is the direct falsification probe for cause (1) — it showed unigram support improves 56–208×, materially addressing that cause, while bigram/trigram support remains ~99% unseen even at 30 minutes, meaning cause (2) (exposure-bias repetition) remains essentially untested by more data alone. P3 (30-min) was never actually trained in this repo, so this falsification test is incomplete.

### 4.7 P3 (30-minute) — status, not a failure
- **OBSERVED**: no training was ever performed; the repository contains only local CPU preparation smokes and one caught, fixed, pre-training device-mismatch bug.
- **DIRECT EVIDENCE**: no `P3_..._RESULT.md`, no `p3_*_metrics.json` (analogous to P1/P2) exists anywhere. `research/poc/model_gates/P3_COLAB_V2_PREPARATION.md` describes an "known step-1 protocol-bug" archival routine, implying at least one real Colab attempt was made and aborted, but its actual metrics are not present locally.
- **ROOT CAUSE**: N/A — this is a data gap, not a confirmed failure. **Do not infer a P3 pass or fail from anything in this repository.**

### 4.8 C1 (Target-C decoder latent, 32/8 continuous regression)
- **OBSERVED FAILURE**: train cosine similarity reaches 0.93 (strong in-sample fit) while validation cosine peaks at only 0.14 (step 100) then decays to 0.08 by step 500; final validation loss (0.667568) ends up *worse* than the untrained initial validation loss (0.600875); all 8 held-out utterances collapse to a similarly bad error magnitude (latent RMSE 0.56–0.58) regardless of content.
- **DIRECT EVIDENCE**: `research/poc/diagnostics/C1_DECODER_LATENT_5MIN_V1.md`, `experiments/swara_speech_poc_v1/reports/c1_decoder_latent_5min_v1.json`. Oracle path (GT latent → decode) remains valid at this scale (10/10 finite/non-silent), isolating the failure to the predictor, not the target representation or codec.
- **ROOT CAUSE**: **UNKNOWN / not explicitly diagnosed anywhere in the repository.** Unlike P2, no labeled RCA document exists for C1. The pattern (strong train fit, near-uniform poor validation fit, worse-than-untrained final validation loss) is circumstantially consistent with H4 (deterministic point-regression producing an averaged/blurred output under held-out uncertainty) and with H6 (insufficient data), but neither is confirmed — no "predict-the-training-mean" baseline was ever computed in this repo to test H4 directly.
- **CONTRIBUTING FACTORS**: same 32/8 data-scale regime implicated across all families (§8, cause #1); a 1024-dimensional continuous target with no distributional/stochastic component, trained with a purely deterministic L1-family loss; no human listening ever recorded, so it is not even known whether the held-out audio was "wrong words," "the same droning sound for every text," or something else — the RCA is limited to embedding-space metrics.
- **RULED-OUT CAUSES**: target-representation invalidity (oracle proves Target C itself remains a lossless-modulo-tiny-error upper bound at this scale); duration/alignment error (GT durations used and asserted exact throughout).
- **WHAT WOULD FALSIFY THIS RCA**: computing the "always predict per-channel training mean" baseline and comparing its validation cosine/RMSE to the trained model's — if the trained model does no better than that baseline, H4 gains direct support; if it does meaningfully better, the failure is more likely pure undertraining/data-scale (H6) than an intrinsic mean-collapse of the deterministic objective. **This is fail-fast diagnostic #2 in §10.**

### 4.9 B1 (Target-B pre-FSQ, 32/8 continuous regression)
- **OBSERVED FAILURE**: train cosine only 0.23 at final checkpoint (budget-limited: 320 steps/40 epochs, an order of magnitude fewer gradient updates than C1's 500 full-batch steps); validation cosine peaks at 0.1486 then ends at 0.1855; exact FSQ token match 0.0000; **self-transition rate on held-out validation reaches 81.68%** at the best checkpoint (vs. ~0% on B0's memorized training data) — the single strongest quantitative "near-static output" signature in the entire dossier.
- **DIRECT EVIDENCE**: `research/poc/diagnostics/B1_PREFSQ_CONTINUOUS_5MIN_V1.md`; the document's own stated diagnosis is limited to "classic train/validation divergence (overfitting past the best checkpoint)" — it does not attempt a deeper mechanistic explanation.
- **ROOT CAUSE**: HIGH-CONFIDENCE contributing cause is under-training relative to C1 (B1's mini-batched 320-step budget vs. C1's 500 full-batch steps is a real confound the repo does not control for), compounding an UNKNOWN residual generalization gap similar to C1's.
- **CONTRIBUTING FACTORS**: mini-batch training introduces additional gradient noise per step vs. C1's full-batch training; same 32/8 data-scale regime.
- **RULED-OUT CAUSES**: target-representation invalidity (oracle PASS); codec/decoder corruption.
- **WHAT WOULD FALSIFY THIS RCA**: rerunning B1 with a training-step budget matched to C1's (500 full-dataset equivalent sweeps) — if the train/validation gap and self-transition signature persist despite matched budget, undertraining is ruled out as the primary explanation and the shared C1/B1 generalization-gap cause becomes the leading hypothesis. Not run in this repo (would require training — out of scope for this analysis-only task; flagged for a future, small, explicitly-scoped run).

### 4.10 F0 (Target-C decoder latent, conditional flow matching, 2-item)
See §7 for the full technical audit. Summary: **OPTIMIZATION**, HIGH-CONFIDENCE. Loss was still monotonically decreasing (not plateaued, not diverged, not NaN) at the fixed 1000-CPU-step budget; every mechanical check (xt path, target velocity, masking, Euler integration direction, conditioning-gradient flow, timestep embedding) matches its unit tests and the documented contract exactly. The comparison to C0's much faster 2-item convergence (500 steps to cosine 0.998) is never discussed in the repo's own F0 document; independently reconstructed here, the difference is attributable to F0's inherently noisier per-step training signal (fresh random `x0`/`t` every step vs. C0's fixed identical target) plus a purely additive (non-AdaLN) timestep-conditioning mechanism — a plausible convergence-rate amplifier, not a structural blocker.

## 6. Core-conditioning forensics

Full technical trace: `src/swara/models/linguistic.py`, `linguistic_composer.py`, `speech_poc_v1.py`, `speech_poc_acoustic.py`, `c0_decoder_latent.py`, `f0_cfm.py`, `src/swara/frontend/{tokenizer,pronunciation,normalizer}.py`, `src/swara/alignment/{ctc_forced,frame_mapping}.py`.

- **Tensor dimensions**: `D_cond = 160` throughout every generator family built on `speech_poc_v1.py` (P1/P2/P3, C0/C0b/C1, B0/B1, F0). Frame-level conditioning delivered to acoustic generators: `[B, T_frames, 160]`.
- **Composition of the 160-d vector**: a character-level bidirectional GRU embedding (64-d chars → 80+80 concat) for grapheme units, or a direct 160-d lookup for pronunciation/punctuation/boundary tokens, plus a token-kind embedding, a language embedding, and a sinusoidal position-in-**unit-sequence** (not frame-sequence) embedding, LayerNorm'd.
- **Identical-conditioning question — YES, confirmed by source**: `MonotonicExpander` performs a literal `torch.repeat_interleave(states, duration_frames, dim=0)` (`speech_poc_v1.py:354`). All frames of one duration-expanded linguistic unit receive a byte-for-byte identical 160-d vector at the point of expansion. No jitter, no positional variation, no acoustic-trajectory signal is added at this stage.
- **Where contextual variation actually arises**: only downstream, inside the generator itself, via two distinct mechanisms — (a) in the causal/AR family (`speech_poc_acoustic.py`), a global absolute-frame-position sinusoidal embedding plus autoregressive feedback of the previously-generated/teacher-forced token; (b) in the non-AR family (C0, F0), only a global absolute-frame-position sinusoidal embedding plus full bidirectional self-attention across all frames (including neighboring, linguistically distinct units). In both families the position signal is **global absolute position in the whole utterance**, not a position normalized within the current unit.
- **Phonetic identity**: **NOT present for ordinary text.** The only phoneme representation (`PRONUNCIATION_ALPHABET_V0`, 30 symbols) is populated exclusively from manual, caller-supplied `PronunciationOverride`s — there is no automatic grapheme-to-phoneme stage. `ctc_forced.py` structurally enforces that every aligned training row (Gate A/B, and therefore all downstream training data) contains zero `PRONUNCIATION`-kind tokens; every lexical unit in every dataset used is `GRAPHEME`.
- **Grapheme vs. phoneme for ordinary words**: characters, always — traced end to end through `LinguisticTokenizer` → `LinguisticValueComposer`'s per-character embedding + bidirectional GRU. Never phonemes.
- **Unseen pronunciation inference**: must be inferred implicitly by the downstream acoustic model from character patterns and duration statistics; there is no automatic G2P generalization mechanism anywhere in the pipeline.
- **Position-within-unit**: **NONE FOUND.** `frame_to_unit` is computed during expansion but used only for provenance/prefix-slicing, never converted into a feature and added to the conditioning vector.
- **Relative acoustic progress (onset/mid/release)**: **NONE FOUND.**
- **Stress/syllable structure**: **NONE FOUND** (repo-wide grep for "stress"/"syllable" in `src/` returns zero hits).
- **F0/energy/prosody conditioning**: **NONE FOUND as an input.** F0 exists only as a training *target* elsewhere in the project (the `f0_cfm.py` model *predicts* an F0-adjacent latent; it does not consume prosody as conditioning).
- **Speaker information**: **NONE FOUND** in the `speech_poc_v1`/C0/C1/B0/B1/F0 path (consistent with a hardcoded single-speaker corpus). Speaker embeddings do exist in the separate, older Qwen-era `generator.py`/`generator_v3*.py` family, which does not share this conditioning path.
- **Alignment Gate A/B certification scope**: both gates certify *structural* validity of the forced-alignment duration supervision (exact frame-sum coverage, monotonicity, no unsupported characters) — they do **not** certify phonetic/linguistic correctness of the (grapheme-only) conditioning representation itself.

**Answer to the central conditioning question**: *Could this conditioning theoretically distinguish the internal acoustic trajectory of a /k/-onset → vowel-center → consonant-release sequence inside one duration-expanded unit?*

**PARTIALLY.** If a generator were strictly frame-independent (pure pointwise mapping, no position signal, no cross-frame mixing), the answer would be a clean NO, since the raw conditioning input is byte-identical across the unit's frames. But none of the architectures examined are frame-independent: the causal family gets a distinguishing global position cue *and* genuine autoregressive state evolution; the non-causal family gets a distinguishing global position cue *and* full self-attention across the sequence (including neighboring, linguistically distinct units, which can leak indirect context). This gives every architecture tested a theoretical *capacity* to differentiate onset/mid/release, but that capacity is an emergent byproduct of absolute-position-plus-attention/autoregression, not a purpose-built intra-unit progress feature — no component anywhere computes or injects a "where am I within this phoneme" signal.

### 6a. Two-item memorization forensic (Step 6)

Every 2-utterance memorization experiment (P1, N1-A/B, N2.0+rollout, C0/C0b, B0, F0) reaches near-perfect fit to its exact training targets. Given: (a) the conditioning vector for a given unit is identical regardless of which sentence it appears in (the composer only sees characters, not sentence identity), and (b) parameter counts (1.4M–43M) vastly exceed the information content of 2 short utterances (a few hundred to ~750 acoustic frames total), the *architectural precondition* for pure sequence memorization (rather than reusable grapheme/phoneme→acoustic mapping) is present in every family. Two additional facts support genuine (if narrow) local-mapping reuse rather than pure whole-sequence memorization: (i) the P1 diagnostic explicitly checked and reported that P1's target tokens are non-repetitive at the bigram level (340/342 frames distinct, every bigram unique) — success there cannot be attributed to trivial sequence simplicity; (ii) the M3B/v1 text-sensitivity control showed correct-text loss strictly lower than wrong-text loss for all 4 memorized items even with identical acoustic history — meaning the model is at least partially keying off the actual (repeated) character content, not merely position-in-training-order.

However, no experiment in the repo performs the controlled test that would cleanly separate these two hypotheses: e.g., holding out a *word* seen during 2-item training but recombined into a novel sentence context, and checking whether its acoustic realization stays consistent. Absent that test:

**C0/B0 evidence of reusable acoustic learning: INCONCLUSIVE.** The evidence is consistent with both "the model learned a local grapheme/phoneme→acoustic mapping that happens to be exercised by exactly 2 sentences" and "the model memorized 2 complete sentence→trajectory pairs using its large excess capacity, with no guarantee of compositional reuse." The C1/B1 failure at 32-item scale (near-zero validation cosine for every held-out item) is itself suggestive that whatever was learned at 2-item scale did **not** transfer as reusable local structure once genuinely novel combinations were required — but this is also fully consistent with "5 minutes is simply not enough data for either hypothesis to succeed," so it does not by itself resolve the INCONCLUSIVE verdict.

### 6b. Unseen-text forensic (Step 7): C1 and B1 at earliest/best checkpoints

- **C1** best validation checkpoint is step 100 (validation loss 0.475157, cosine 0.1414), degrading thereafter to step 500 (loss 0.667568, cosine 0.0805) even as train cosine climbs to 0.93 — a textbook overfit-past-best-checkpoint curve. All 8 held-out utterances land in a narrow, nearly uniform error band (RMSE 0.56–0.58) regardless of content, length, or duration — i.e. the failure does **not** obviously correlate with any one held-out item being especially long, short, or lexically unusual; it is broad and undifferentiated across the whole validation set.
- **B1** best validation checkpoint is step 40/epoch 5 (loss 0.470893, cosine 0.1486), with self-transition rate already 0.8168 at that *best* checkpoint — meaning even the best-scoring B1 checkpoint's held-out output is already dominated by frame-to-frame repetition, not just the final, more-overfit checkpoint.
- **Neither experiment's report computes or discusses** per-utterance breakdowns by unseen-word count, unseen-character-sequence count, sentence length, or duration distribution as explanatory variables — this data (utterance IDs, transcripts, and durations) exists in the underlying manifests but the *correlation analysis* itself was never performed and is not reproducible from the JSON reports alone without a small new script. **This is flagged as a fail-fast diagnostic candidate (§10, diagnostic #3), not resolved by existing evidence.**
- What the evidence rules out: duration/alignment numerical error (GT durations, exact frame-sum assertions in both); target-representation invalidity (oracle passes for both at this scale); catastrophic silent/NaN output (all held-out audio remained finite and non-silent in both).
- What the evidence is consistent with but does not confirm: general OOD conditioning collapse (near-uniform error regardless of content) more than a length- or duration-specific effect, since the error band is narrow across a val set that does include short and long utterances (per the R0 panel's stated length-bucketed selection policy, though C1/B1's own 8-item validation split was not itself re-verified for a length spread breakdown here).

| Timestep embedding | Sinusoidal, genuinely varies at train (random) and inference (deterministic sweep); no frozen-`t` bug. |
| Euler integration direction | t: 0→1, x0=noise→x1=target, consistent with training convention; deterministic and seed-diverse per unit tests. |
| Train/inference consistency | Dropout correctly toggled (train/eval); no CFG/AdaLN to diverge; no length/masking mismatch found. |
| Generated latent distribution | Cosine similarity to real target rises monotonically across checkpoints (0.10→0.21 and 0.11→0.28 for the two utterances) but normalized RMSE stays >1 (generated error exceeds the real latent's own RMS magnitude) at the final checkpoint; decoded-waveform peak/clipping *increases* over training even as cosine improves, suggesting an under-converged, still-drifting velocity field rather than a stable fit. |

**Why did F0 fail to memorize where C0 (same target, similar conditioning mechanism) succeeded?** Not discussed anywhere in the repo's own F0 documentation — reconstructed independently here: C0 reaches near-perfect fit (cosine 0.998) in 500 full-batch steps of a *fixed, identical* regression target; F0's per-step training signal is a *freshly resampled* `(x0, t)` pair every step (a harder, higher-variance objective by construction), and F0 uses purely additive (non-AdaLN) timestep conditioning, a mechanism generally weaker than adaptive-normalization conditioning in the flow-matching/diffusion literature. F0's loss was still strictly decreasing, not plateaued, when its 1000-step CPU budget ended.

**Classification: OPTIMIZATION, HIGH-CONFIDENCE.** IMPLEMENTATION_BUG is ruled out (every mechanical check passes its unit tests). CONDITIONING is ruled out (identical, working mechanism to C0). TARGET_GEOMETRY is not supported (for a fixed single target per utterance, the conditional velocity field is theoretically exactly recoverable, i.e. the loss floor is 0, not an irreducible multimodal floor). The residual explanation is an under-provisioned training budget for an intrinsically higher-variance per-step objective, with the additive-only timestep-conditioning design as a plausible convergence-rate amplifier (a FLOW_ARCHITECTURE-flavored contributing factor, not shown to make convergence impossible).

## 8. Ranked root causes

1. **(≈75% confidence) Insufficient training-data scale for generalizable text→acoustic learning at the tested ~5-minute/32-utterance regime.** This is the narrowest pattern that recurs identically across every architecturally distinct family tested — discrete 65,536-way AR classification (P2), non-AR flat/FSQ classification with no history (N1), AR with causal acoustic history (N2), non-AR continuous 1024-d regression (C1), and non-AR continuous 8-d regression (B1) all trivially memorize 2 utterances and all collapse to near-chance/near-static held-out output at 32/8. Objective, architecture, causality structure, and target representation vary maximally across these five; the qualitative outcome does not. No experiment in the repo isolates data scale from architecture/objective by holding one fixed while sweeping the other across intermediate sizes (e.g. 8 or 16 train utterances), so this is the leading but not dispositive candidate.
2. **(≈55% confidence) Grapheme-only, position-within-unit-blind linguistic conditioning is too coarse to support generalizable (as opposed to memorized) fine acoustic-trajectory synthesis.** Structurally confirmed by direct source inspection (§6): no phoneme, stress, prosody, or intra-unit-progress signal exists anywhere in the 160-d conditioning vector, and frames within one duration-expanded unit are byte-identical at the point of expansion. This is a real, load-bearing architectural limitation, but it is confounded with cause #1 — no controlled phoneme-vs-grapheme or position-embedding ablation has been run to isolate its effect size, so it remains a strong structural hypothesis rather than a measured effect.
3. **(≈50% confidence, architecture-scoped) Confirmed exposure bias / train-inference mismatch in every autoregressive family tested.** Directly measured and high-confidence for v3.1 (14.6× history/text sensitivity ratio), N2.0 (99.9%→0.204% TF/free divergence), and P2 (97.7% self-repeat attractor). Explicitly does not extend to non-autoregressive families (C1/B1), which structurally cannot exhibit this exact mechanism yet still fail — so this is a real, confirmed, but partial cause, not the common denominator across all failures.
4. **(≈35% confidence, continuous-regression-scoped) Deterministic point-regression objective may be collapsing to an averaged/blurred output under held-out uncertainty (H4).** Circumstantial support from C1's near-uniform validation error and worse-than-untrained final validation loss, and from B1's 81.68% held-out self-transition rate — but never directly tested against a computed "predict-the-mean" baseline anywhere in the repo, so this remains plausible rather than confirmed.
5. **(≈25% confidence, component-scoped) Under-provisioned capacity/training-budget for specific sub-components.** Confirmed for the Qwen residual-codebook GRU (40–50× smaller than Qwen's reference sub-talker, independent-head scaling alone insufficient) and for F0's fixed 1000-CPU-step budget (loss still decreasing, not plateaued, at cutoff). Explicitly not shown to be the dominant, project-wide bottleneck — the project's own retrospective disproves "model size is the primary bottleneck" as a general claim, and this cause is scoped to the two specific components named.

**Is the common core architecture/conditioning itself the root cause?** **SUSPECT, not CONFIRMED.** It is a real, structurally-verified limitation (cause #2 above) but is confounded with the data-scale cause (#1) in every experiment that has been run, and the same conditioning pipeline supports near-perfect memorization in every family — so it is not so impoverished that it fails outright; whether it is fine-grained enough to support *generalization* specifically (as opposed to data scale being the binding constraint) is the single most important open question this RCA leaves unresolved (see §9, question 1, and §10, diagnostic #1, which is designed to disambiguate exactly this).

## 9. Remaining unknowns

1. **Whether conditioning granularity or data scale is the binding constraint on generalization** — the two leading causes (§8, #1 and #2) are confounded in every experiment run so far; no ablation holds one fixed while varying the other.
2. **Why the N2 five-minute formulation failed** — explicitly recorded as UNKNOWN by the project's own retrospective (`EXPERIMENT_EVIDENCE_MATRIX.md` row N2-5: "Why: alignment/prefix/target/data/capacity" left open).
3. **What C0/C0b/C1/B0/B1/F0/R0 audio actually sounds like** — no human listening has ever been completed for any of these seven experiments; all machine evidence is proxy-metric-only (loss, cosine, self-transition rate). It is unknown whether C1/B1's held-out failures sound like "wrong words," "a constant drone," "silence with noise," or something else — this materially limits confidence in any RCA that depends on characterizing *what kind* of failure occurred perceptually.
4. **Whether P3 (30-minute, flat-token AR) would pass or fail** — never actually trained in this repository; only local CPU preparation and one caught, fixed, pre-training device-mismatch bug exist. The statistical-support audit statistically *justifies* attempting it but explicitly does not predict its outcome.
5. **The exact severity of the "known step-1 protocol bug" referenced in P3-v2 preparation** — a real Colab attempt appears to have occurred and been archived, but its quantitative content (the similarity value that triggered the immature-gate stop) is not present anywhere in this local checkout.
6. **Whether Distill-NeuCodec's own encode→decode fidelity is actually good** — direct documentation conflict: the retrospective claims a completed blind listening pass (9 original-preferred / 2 codec-preferred / 9 no-difference, "codec accepted"), while the on-disk `DISTILL_NEUCODEC_LISTENING_SCORECARD.md` was found completely blank by direct file inspection, and the only completed objective metric (mean SI-SDR −9.02 dB) is, at face value, weak. This should be resolved (by locating whatever produced the retrospective's specific numbers, or by re-running the blind listening pass) before placing further weight on "the codec is proven good."
7. **Whether the residual (CB1–CB15) collapse in the Qwen family is fundamentally a capacity problem or something else** — v3.3's independent-head intervention only partially improved it; no experiment tests a materially larger/deeper residual model to isolate capacity as the binding constraint versus, e.g., the shared-GRU recurrence structure itself.
8. **Whether B1's poor train fit (cosine 0.23) reflects the target representation, or simply an under-matched training budget relative to C1** (320 mini-batched steps vs. C1's 500 full-batch steps) — not disentangled by any experiment in the repo.

## 10. Maximum five fail-fast diagnostics

All five are read-only-model / minutes-scale, require **no new training run** beyond a small number of forward passes or a few dozen gradient steps on already-cached data, and are designed to disambiguate the ranked causes in §8 and the unknowns in §9.

### Diagnostic 1 — Phoneme-conditioned vs. grapheme-conditioned nearest-neighbor probe (disambiguates §8 #1 vs #2)
- **HYPOTHESIS**: if conditioning granularity (not data scale) is the binding constraint, then two acoustically distinct sub-word contexts that the current grapheme composer would embed near-identically (e.g., two positions with the same character but different phonetic realization) should be conflated more than two contexts a phoneme representation would keep separate.
- **CHANGE**: none to the model. Take the already-trained C0/C0b checkpoint's frozen `LinguisticValueComposer` output for every character/word span in the 2-item training set; compute pairwise cosine similarity of composer output vectors for spans with the same spelling but different true acoustic duration/context, vs. spans with different spelling. Purely an inference-time embedding-space analysis.
- **CONSTANTS**: no weight updates, no new data.
- **MAX RUNTIME**: minutes (a few dozen forward passes through an existing checkpoint on CPU).
- **EXPECTED RESULT IF HYPOTHESIS TRUE**: same-spelling/different-acoustic-context spans cluster tightly (near-identical embeddings) regardless of measurably different ground-truth duration or spectral character, indicating the conditioning genuinely cannot distinguish them.
- **EXPECTED RESULT IF FALSE**: same-spelling spans already show measurable embedding separation (e.g. from the position-in-sequence or neighboring-token context folded in by the GRU), suggesting conditioning granularity is not the binding constraint and the search should refocus on data scale or objective.
- **DECISION AFTERWARD**: if TRUE, prioritize a small phoneme-conditioning or position-within-unit-embedding ablation (small architecture change, not in scope for this analysis-only task, but a well-justified next step) over further data collection; if FALSE, prioritize data-scale/objective causes.

### Diagnostic 2 — Frozen "predict-the-training-mean" baseline for C1/B1 (disambiguates §5 H4)
- **HYPOTHESIS**: C1/B1's held-out failure is a deterministic-regression mean-collapse (H4), not a total learning failure.
- **CHANGE**: no training. Compute, from already-cached C1/B1 training targets, the per-channel mean (and per-channel mean trajectory averaged over duration-normalized position) of the training set's Target-C/Target-B latents. Score this static baseline against the same 8 held-out validation utterances using the exact same cosine/RMSE metrics C1/B1 already report.
- **CONSTANTS**: same validation set, same metrics, same normalization statistics already saved in `target_normalization.npz`-equivalent files.
- **MAX RUNTIME**: minutes (pure numpy/tensor arithmetic on already-cached arrays, no model forward pass needed).
- **EXPECTED RESULT IF HYPOTHESIS TRUE**: the trained C1/B1 models perform no better (or only marginally better) than this static mean baseline on held-out cosine/RMSE — confirming the model learned essentially nothing beyond the dataset's global average.
- **EXPECTED RESULT IF FALSE**: the trained models measurably outperform the static mean baseline, indicating partial, real (if insufficient) generalization — shifting weight toward "needs more data/capacity" rather than "objective structurally collapses to the mean."
- **DECISION AFTERWARD**: if TRUE, the deterministic point-regression objective itself becomes a stronger root-cause candidate, motivating (in a future, separately-scoped effort) a distributional/stochastic objective (e.g. the already-implemented F0 flow-matching approach, trained for longer, or a mixture-density head) rather than continued Smooth-L1 regression. If FALSE, deprioritize H4 and focus on data-scale/conditioning causes instead.

### Diagnostic 3 — Held-out failure correlation sweep for C1/B1 (resolves §6b's flagged gap)
- **HYPOTHESIS**: C1/B1's 8 held-out failures correlate with a specific measurable property (unseen word count, unseen character bigrams, utterance length, or duration extremity) rather than being uniformly bad regardless of content.
- **CHANGE**: no training, no model changes. Using the already-existing train/val manifests and transcripts, compute per-validation-utterance: count of words never seen in the 32-item training set, count of character bigrams never seen in training, utterance length in words/frames, and total duration. Correlate each against the already-reported per-utterance cosine/RMSE values from `c1_decoder_latent_5min_v1.json` and `b1_prefsq_continuous_5min_v1.json`.
- **CONSTANTS**: existing manifests, existing reported per-utterance metrics — purely a post-hoc statistical analysis script.
- **MAX RUNTIME**: minutes (small Python script over already-cached JSON/JSONL).
- **EXPECTED RESULT IF HYPOTHESIS TRUE**: a clear correlation (e.g. utterances with more unseen words score worse), narrowing the cause toward lexical/OOD generalization specifically.
- **EXPECTED RESULT IF FALSE**: uniformly poor scores with no correlation to any of these variables (consistent with what §6b already observed informally — a narrow RMSE band 0.56-0.58 for C1 across all 8 items) — reinforcing that the failure is a broad, content-independent collapse rather than a targeted OOD weakness, which points more toward cause #1 (data scale) or #4 (objective collapse) than toward conditioning-specific lexical gaps.
- **DECISION AFTERWARD**: if TRUE, prioritize increasing lexical/phonetic coverage in training data over other interventions. If FALSE (as the existing narrow-RMSE-band evidence already suggests), do not pursue targeted vocabulary-coverage fixes; focus on cause #1/#4 instead.

### Diagnostic 4 — Exact Mel/C0-style single-utterance CFM overfit re-check with matched step budget (resolves §7's open comparison)
- **HYPOTHESIS**: F0's failure to match C0's fast 2-item convergence is purely an optimization/step-budget issue (§7 conclusion), not an architectural ceiling.
- **CHANGE**: none to the architecture. Using the exact existing F0 model/script, extend training on the same 2 cached utterances for additional steps beyond the original 1000 (e.g. to 2000-3000, still well within "minutes" on CPU given the original 1000 steps took 214.96s), tracking whether loss continues to decrease and cosine similarity continues to climb past the 0.21-0.28 range already observed.
- **CONSTANTS**: same 2 utterances, same normalization, same architecture, same optimizer — only total step count changes.
- **MAX RUNTIME**: well under 10 minutes on CPU (linear extrapolation from the already-measured 214.96s/1000-steps).
- **EXPECTED RESULT IF HYPOTHESIS TRUE**: cosine similarity continues climbing meaningfully toward C0-like territory (e.g. >0.7) and loss continues falling, confirming pure under-convergence.
- **EXPECTED RESULT IF FALSE**: loss/cosine plateau well below C0's memorization level despite the extra budget, indicating a real architectural ceiling (e.g. the additive-only timestep conditioning) rather than pure optimization.
- **DECISION AFTERWARD**: if TRUE, F0 remains a viable direction pending a real (non-toy) training budget; if FALSE, prioritize an AdaLN-style timestep-conditioning architecture change before further F0 investment (a future, separately-scoped change, not performed here).

### Diagnostic 5 — Position-within-unit embedding ablation, inference-only sensitivity check (further disambiguates §8 #2)
- **HYPOTHESIS**: the absence of a position-within-duration-expanded-unit signal (confirmed absent in §6) measurably limits a generator's ability to produce different outputs for different frames of the same unit, beyond what global absolute position already provides.
- **CHANGE**: no training. Using an already-trained checkpoint (e.g. C0 or C0b), run one forward pass and record the generator's per-frame hidden-state variance *within* single long duration-expanded units (there are several units with 5+ frames in the C0b `AGRI_7084` utterance) versus *across* different units. If the within-unit variance is a large fraction of the across-unit variance, the existing global-position + attention/autoregression mechanism is already providing meaningful intra-unit differentiation; if within-unit variance is near-zero relative to across-unit variance, the conditioning-plus-architecture combination is not meaningfully distinguishing intra-unit frames even where it structurally could.
- **CONSTANTS**: existing checkpoint, existing cached data, no architecture change — an inference-time introspection/hook script only.
- **MAX RUNTIME**: minutes (one forward pass, a few hidden-state extraction hooks).
- **EXPECTED RESULT IF HYPOTHESIS TRUE**: near-zero within-unit hidden-state variance relative to across-unit variance, confirming the theoretical PARTIALLY answer in §6 is, in this trained checkpoint's practice, closer to NO.
- **EXPECTED RESULT IF FALSE**: substantial within-unit variance already present, suggesting the existing global-position/attention mechanism is doing real work and an explicit position-within-unit feature would add less marginal value than expected.
- **DECISION AFTERWARD**: if TRUE, an explicit position-within-unit embedding becomes a well-justified, low-risk architecture change to test next (not performed here — out of scope); if FALSE, deprioritize that specific change and focus remaining effort on data-scale (#1) and objective (#4) causes instead.

## 11. Explicit "do not do next" list

- **Do not** run another large (30-minute-scale or larger) training run on any current formulation before running the five diagnostics in §10 — none of the open causal questions they're designed to resolve require new training data or a large compute budget, and running P3 now would not by itself disambiguate data-scale from conditioning-granularity causes (§8, #1 vs #2), which is the single most important open question.
- **Do not** conclude the flat-65,536-token NeuCodec representation is intrinsically unviable — this has been explicitly ruled out by the P1/P2 RCA (codec oracle works, P1 memorizes perfectly, NeuTTS uses the identical representation at scale) and is a disproved assumption in the project's own retrospective.
- **Do not** conclude model capacity is the primary bottleneck and scale up parameters — this is a disproved assumption in the project's own retrospective (explicit decision to hold the PoC at 10-20M parameters) and capacity was only confirmed as a proximate cause for two narrowly-scoped components (Qwen residual GRU, F0's step budget), not project-wide.
- **Do not** treat the R0 bake-off's "PROMISING" machine classifications, or any of C0/C0b/C1/B0/B1/F0's oracle/loss/cosine metrics, as validated speech quality — none of these seven experiments has a completed human-listening judgment, and R0's own explicit stop condition ("No C0 implementation or training is authorized by this report" pending human review) was not honored by subsequent work. Any further training decision should not repeat this pattern.
- **Do not** attribute the Qwen-family residual-codebook failure to exposure bias or history-domination — it was directly and explicitly ruled out (CB1 collapses before any autoregressive exposure to prior residual tokens is even possible); the confirmed cause there is shared-module capacity/underfitting.
- **Do not** cite the Distill-NeuCodec blind-listening result as settled evidence of codec fidelity without first resolving the direct conflict identified in §9, item 6 (retrospective claims a completed, favorable blind pass; the on-disk scorecard file is blank).
- **Do not** implement any of the five diagnostics' natural "next architecture change" follow-ups (phoneme conditioning, position-within-unit embedding, AdaLN timestep conditioning, mixture-density/stochastic objective, larger residual model) without first running the corresponding read-only diagnostic in §10 — each is designed to be a fast, cheap gate before committing to a training-affecting change.
- **Do not** modify `src/swara/models/speech_poc_v1.py` or `tests/test_speech_poc_gate_c.py` further as part of any RCA follow-up without first reviewing the currently uncommitted working-tree diff (the P3 device-mismatch fix + new `for_inference` method) — this analysis treated that diff as pre-existing, uncommitted, in-progress work, not as something to alter.
